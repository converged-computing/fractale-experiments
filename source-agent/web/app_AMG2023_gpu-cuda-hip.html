us.anthropic.claude-opus-4-8 — what the model said

AMG2023 GPU topology/memory
GPU support inherited from hypre (build with AMG_WITH_CUDA / AMG_WITH_HIP; SYCL for Intel). hypre_bind_device binds one device per rank before HYPRE_Init -> one GPU per MPI rank, so multi-GPU runs use one rank per device. accelerator.kind=cuda is the primary path (also rocm/sycl). gpu_aware_mpi is likely for on-node GPU-to-GPU halo exchange but not proven in this driver source.
mpirun -np <P*Q*R> ./amg -problem 1 -n <nx> <ny> <nz> -P <px> <py> <pz> -memory_device -exec_device

us.anthropic.claude-sonnet-5 — what the model said

AMG2023 GPU build (MPI + CUDA/HIP, one GPU bound per MPI rank via hypre_bind_device)
Variant with AMG_WITH_CUDA or AMG_WITH_HIP enabled (CMakeLists.txt:22-23,50-69). amg.c calls hypre_bind_device(myid,num_procs,comm) before HYPRE_Init (amg.c:360) to bind each MPI rank to a GPU, indicating one-GPU-per-rank placement; README also states GPU support via CUDA/HIP/SYCL (README.md:13). Same MPI SPMD PxQxR decomposition and neighbor-exchange communication pattern as CPU variant, but compute offloaded to device; still relies on host MPI for inter-rank halo exchange/reductions, likely GPU-aware MPI. No checkpoint or parallel I/O found.
mpirun -np <P*Q*R> --gpus-per-task 1 ./amg -P <px> <py> <pz> -n <nx> <ny> <nz>
